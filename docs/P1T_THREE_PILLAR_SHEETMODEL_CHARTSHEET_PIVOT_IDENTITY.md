# P1T-A — Three-pillar sheet model, Chartsheet and Pivot item identity

P1T-A continues the P1S goal of making Basic XLSX read/write, Charts and PivotTables stronger than an ordinary object-only workbook API. The focus is semantic ownership and interoperability rather than adding isolated properties.

## Basic XLSX read/write — first-class workbook tab model

XL++ now distinguishes worksheet storage from workbook tab order. Existing `sheetCount()`, `sheetNames()` and `operator[]` remain worksheet-only for source compatibility. New APIs expose the real mixed workbook `<sheets>` order:

- `WorkbookSheetKind::{Worksheet, Chartsheet}`
- `WorkbookSheetDescriptor`
- `workbookSheetCount()`
- `workbookSheetNames()`
- `workbookSheets()`
- `moveWorkbookSheet()`

A first-class `Chartsheet` type owns one chart and participates in the workbook tab order. `addChartsheet`, lookup, rename and remove are supported. Imported chartsheets are preservation-backed until the chart is mutated; removing an imported chartsheet retires its exclusive chartsheet/drawing/chart relationship closure rather than leaving orphan package parts.

`LoadOptions::maxChartsheets` bounds materialized chartsheet count. `StreamingWorkbookReader` keeps worksheet row streaming unchanged and adds `chartsheetNames()` plus `workbookSheetNames()` so a chart-only tab is not mistaken for a row source.

The package relationship validator counts Chartsheets separately and validates their drawing ownership chains.

## Charts — chart-only sheet ownership

Generated Chartsheets use native OOXML parts:

- `xl/chartsheets/sheetN.xml`
- `xl/chartsheets/_rels/sheetN.xml.rels`
- a DrawingML drawing part
- a chart part
- workbook relationship type `/chartsheet`
- the Chartsheet content type override

The P1S multi-plot model works on Chartsheets as well as worksheet drawings. Regression creates a Bar + Line combination with a secondary Y axis on a Chartsheet and reloads it as two plot groups.

An independent openpyxl 3.1.5 host check recognizes the generated workbook as `Data`, `Chart View`, `Notes`, separates worksheets from chartsheets, and materializes the chart as Bar + Line subplots with the expected primary/secondary axis IDs. A fixture originally generated by openpyxl is also loaded and round-tripped by XL++; untouched Chartsheet XML remains byte-preserved.

## PivotTables — logical typed item identity

Pivot shared-item ordinal `x` values are physical cache indexes, not stable semantic identities. P1T adds a logical binding to `PivotFieldItem`:

- `cacheValue`
- `cacheValueKind`
- `hasCacheValue`
- `bindCacheValue()`

and higher-level `PivotField` helpers:

- `addCacheValueItem(value, kind, hidden)`
- `hideCacheValue(value, kind)`
- `showCacheValue(value, kind)`

When serializing, XL++ resolves logical `(PivotCacheValueKind, value)` against the current typed shared-item table. If cache edits change first-seen order or compact shared items, hidden/item semantics follow the value instead of a stale ordinal.

The P1T regression begins with typed category order `[A, B, C]`, hides logical string `B`, edits records so the physical shared-item order becomes `[B, C, A]`, and verifies the Pivot item is repaired to `x=0`. Save/load retains both the repaired physical index and logical typed identity.

## C ABI

The C API now exposes the P1T mixed workbook tab model and Chartsheet lifecycle, plus P1S chart generation primitives needed to construct generated combo charts from non-C++ consumers:

- workbook tab count/name/kind/move
- chartsheet create/count/lookup/rename/remove/chart access
- scatter style
- generated chart plots and secondary-axis identity
- series-to-plot insertion
- bubble-size reference

`xlpp_capi_smoke` generates, saves and reloads a Chartsheet combo through the C ABI.
